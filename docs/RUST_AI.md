# The gateway's AI routes (phase 5)

Behind `ai` in `ND_RUST_ROUTES` (`docs/RUST_GATEWAY.md`). Same rule as every other gateway route: it answers only what it is sure of,
and everything else goes to Python unchanged.

| Route | What the gateway does | Stays Python's |
|---|---|---|
| `POST /api/chronicler/ask` | The Chronicler: the system prompt `build_chronicler_system_prompt` builds (facts - a player's without GM-only ones -, the entities the question finds through FTS5 with the same column weights, the visibility filter and secret-only matches dropped, their excerpts picked by `best_matching_excerpt`, their notes, the GM's AI instructions), the same request to an Unsloth Studio backend (`/v1/models` to resolve the model, `/v1/chat/completions` streamed, Settings' generation options translated as `app/llm_client.py` does), and the same SSE answer: `note`, `thinking` (the backend's reasoning and a literal `<think>` block), `token`, `error` (Python's texts for a backend error, an error event mid-stream and an empty answer), `[DONE]`, a keep-alive comment every 12 s. A GM's own model choice (resolved against `/v1/models`) and Thinking choice (`thinking_predict` added) are honoured as Python does; a player's are ignored. A player's 3 s cooldown (429) and the 30 s answer cache are kept by the gateway. | The legacy Ollama backend (no Studio key), an `https://` backend address, a note stored as HTML, a failure of the FTS5 index (Python's ILIKE fallback) |
| `POST /api/ai/stream` | The AI Chat page and the entity page's Ask AI: the access check (a GM, or a world with `players_can_ask_ai` / `players_can_use_ai_chat`), messages with document attachments folded in (12,000 characters each), the model (a GM's own, else the surface's default from `ai_models.json` beside the database; a player pinned to `chat` / `ask_ai`), the preset options through `_clamp_options`' allowlist and ranges, a player's system text cut at 50,000 characters, Thinking's `num_predict` widening; then the same request and SSE as the Chronicler (no cache, no cooldown). | A refused caller (Python's 403), picture or audio attachments, an option given as text, a body Pydantic would reject or coerce |
| `POST /api/npc-talk/<id>/stream` | Talking to an NPC: the same access check, the NPC as the caller's own entity list shows it (characters, creatures, organizations), the in-character system prompt `_identity_context` builds (sheet with `[gmonly]` stripped for a player, custom fields, the GM's personality direction, notes, visible related entities, the GM's standing notes), the last 40 turns of the stored conversation, the `ask_ai` default model, Thinking; the same SSE, and both turns saved to the `chat_sessions` row (created on the first answer) only when the answer finished cleanly with text in it. | A GM's lore retrieval (`use_rag`), a note stored as HTML, a custom field holding a decimal number or nested value, a non-ASCII kind |
| `POST /api/ai/assist` | The editors' AI Assist panel, for a free-text operation (expand, improve, deslop, summarize, analyze, translate, custom, rules rewrite, world summary, folk tale, code edit) by a GM or a GM-assistant: the operation's system prompt (`app/ai_assist.py`, carried in `app_data.json` as `assist_systems`), the user text `_compose_user` builds (the GM instruction, Kind / Name / Summary / Tags, the content), translate's target language, the model (the request's, else the `assist` default, else the configured one), `_free_text_call`'s options (Thinking's widening, else a 1,024-token cap when nothing bounds the answer); one non-streamed `generate_chat` call with the retry of a refused Thinking request, the `<think>` block stripped, `_clean_degenerate_recap`, and `{op, mode, text, model}` - or a 502 with the failure text. | The JSON operations (`suggest`, `table_entries`), lore retrieval (`use_rag`), every 400 (an unknown operation, a missing instruction or content, content over 60,000 characters), a caller who may not edit content |
| `/api/kiy/*` | Nothing. | All of it: `generate` fetches 16 outside sources and samples the play library at random (no parity to check), `build-model` needs a local Ollama |

Code: `rust/nd-gateway/src/ai.rs` (the route, the backend client, the stream), `rust/nd-gateway/src/retrieval.rs` (`app/retrieval.py`'s entity
search, excerpts and context lines; `app/ai_instructions.py`).

Tests: `tests/test_gateway_ai.py` runs a fake Studio both Python and the gateway talk to. It checks that the requests reaching it (system
prompt, model, options, key) and the SSE answers are the same, for a GM and a player, from the cache too, and for backend errors, an
error mid-stream and empty answers; for `/api/ai/stream` and NPC talk too, the NPC's saved conversation compared after each turn.

A Thinking request the backend refuses with a 400 (`_is_thinking_rejection`: Ollama's wording, or any 400 not about the context, a missing
model and the like) is retried once without Thinking, with the `<|think|>` token at the head of the system prompt for a model known to
think (Unsloth's built-in Gemma 4, or Settings' per-model "thinking" tick), as `stream_chat` does - on every route here.

Known differences: when the backend cannot be reached at all, the `error` text names the failure in the gateway's words, not httpx's
(`[AI unavailable: ConnectionError: ...]` either way). The cache and the cooldown live in the process that answers. With `ai` on, that
is the gateway for every request it serves, so a question answered by Python a moment earlier is not in the gateway's cache.
