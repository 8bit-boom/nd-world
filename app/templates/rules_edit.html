Cheatsheet — Markdown superpowers
  • :::tip, :::note, :::warning, :::danger, :::lore, :::collapse, :::gm — a themed block, closed by a line containing only ::: (an optional title goes on the first line: :::tip Read this first). :::gm blocks are removed from the page for players entirely; :::collapse renders a click-to-open section (default title "Details").
  • ```statblock fence — the first line is the block's name, following Label: value lines become rows (split on the first colon), other lines render as free text; a 📋 Copy button copies the raw text.
  • Unknown :::type names still render (as a note callout titled with the type name) — content is never silently dropped.
  • rules.json overlay keys: sections maps a heading slug (the part after # in a TOC link) to {"icon", "title", "players_visible", "order"}; tabs is a list of {"id", "label", "sections": [slugs]} — listed slugs show in that order, unlisted sections land in a trailing "More" tab; players_visible: false hides the section from players (GMs still see it). Full guide with a worked example: docs/RULES_OVERLAY.md.
📖 How to build the rules.json overlay — step by step

What it's for. The overlay is UI metadata on top of your markdown: icons, custom section titles, reordering, per-section player visibility, and tab groups. It never changes the rule text — /rules/download.md keeps serving the pure markdown, overlay or not.

Step 1 — get the section slugs. Every ##/### heading becomes a section whose slug is the lowercase heading with spaces and punctuation collapsed to - — e.g. ## Part II — Races & Optional Systems becomes part-ii-races-optional-systems. The easiest way to read them off your own document: open the Rules page and copy the target of any TOC link (everything after the #).

Step 2 — write the JSON. Two optional top-level keys: sections (slug → settings) and tabs (grouping). Example:

{
  "sections": {
    "part-i-core-rules": { "icon": "⚔️", "order": 1 },
    "part-ii-races-optional-systems": { "icon": "🧬", "order": 2 },
    "appendix-b-editorial-notes-source-map": { "players_visible": false }
  },
  "tabs": [
    { "label": "⚔️ Core", "sections": ["part-i-core-rules"] },
    { "label": "🧬 Races", "sections": ["part-ii-races-optional-systems"] }
  ]
}

Slugs not mentioned in tabs land in a trailing "More" tab; sections missing from sections keep their natural title and position. players_visible: false is the data-driven version of a :::gm block — removed server-side for non-GM viewers, and the TOC never links to it.

Step 3 — apply it. Either paste the JSON into the overlay textarea above and Save (invalid JSON is rejected with the parse error), or save it as a .json file and upload it through the Import from JSON box at the top of this page — an overlay-only file (no rules_md) is accepted and updates the UI without touching your markdown.

Validation & safety. A stored overlay that fails validation is ignored on the Rules page (with the ⚠️ banner above), never a broken page. Unknown section slugs in tabs are harmless. Changes take effect on the Rules page immediately — no restart.

Full guide with a worked example: docs/RULES_OVERLAY.md on GitHub.
