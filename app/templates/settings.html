⚙ Settings

Image uploads

Portraits and entity images (NPCs, creatures, organizations, locations, and everything else) are converted on upload to save storage space, at 90% quality — AVIF compresses best, WebP has the widest browser/tool support. SVGs are never converted (they're vector, not raster). The two formats are chosen independently for static images and for animated GIF/WebP uploads (which get re-encoded keeping every frame, not just the first) — set either to "Don't convert" to leave that category in its original format.

Ollama generation tuning

Two different things live on this page. Generation tuning below is sent with every AI request (recaps, Ask AI, fact extraction) — it applies immediately, no restart. Server tuning further down configures the Ollama process itself (flash attention, KV cache type, parallelism); Ollama only reads those at start-up and has no runtime API for them, so saving that section writes them to a file the "ollama" container reads on its next restart, and tells you when a restart is due. Leave any field blank here to fall back to Ollama's/the model's own default.

Session Recap and Condense actions temporarily widen this cap (by 4096 tokens by default) when 🧠 Thinking is on, so hidden reasoning can't use up this whole budget before the visible answer gets written.
Advanced sampling & runtime

num_ctx/num_gpu above and num_batch/num_thread/main_gpu/use_mmap below all take effect on the model's next load (a few seconds), not mid-generation. Everything else here applies to the very next request.

Deprecated (ignored by current Ollama)

Current Ollama's Options struct has no mirostat fields at all — sending these logs "invalid option provided" server-side and is otherwise ignored. Kept only for an older Ollama server, and so a value you'd already saved here isn't silently discarded.
